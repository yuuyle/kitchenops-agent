# KitchenOps Agent 操作手順

審査員の方が公開URLからアプリを試すための手順書です。所要時間は 5〜10分。

- 公開URL: **https://kitchenops-agent-yuuya-20260601.azurewebsites.net**
- ログイン不要。URLを開くだけで全機能が利用できます。
- 推奨ブラウザ: Chrome / Edge（カメラAPI と最新CSSが安定）。スマートフォンでも動作します。

## 0. 起動確認

URLを開くと、左側にタブメニュー（**カメラ / 献立 / レシピ / 在庫 / 家族**）、右下に **Microsoft AI** パネルが表示されます。

最初に表示する画面は **カメラ** タブです。

## 1. Microsoft AI 接続確認（最重要）

審査基準の Microsoft AI 利用を確認するための最初のステップです。

1. 画面右下の **「Microsoft AI」** パネルに注目
2. 以下が表示されていることを確認:
   - `Azure OpenAI` → **configured** バッジ
   - `Azure AI Vision` → **configured** バッジ
3. ヘッダー右上のステータスが **「Azure AI」** になっていることを確認（OpenAI API ではなく Azure を使っている証拠）

```
[Microsoft AI]
  ● Azure OpenAI    configured
  ● Azure AI Vision configured
```

このパネルは画面のどのタブにいても常に確認できます。

## 2. 入庫デモ（実カメラ + Azure AI 経路）

カメラを使って実際の食材を Azure AI で認識させるデモです。

### 推奨食材

正規化カタログにあるため判定が安定します:
- バナナ、トマト、じゃがいも、キャベツ、牛乳

パッケージ食品や複数食材を同時に映すと、判定が近い候補に寄ることがあるので、**1種類ずつ** 映すのが確実です。

### 操作

1. **カメラ** タブ（最初に表示される画面）を開く
2. モードが **「登録」** になっていることを確認
3. **「開始」** ボタンを押す → ブラウザのカメラ許可ダイアログで「許可」
4. カメラ映像が表示されたら、**「自動スキャン」** が ON であることを確認（デフォルトON）
5. 食材を1種類だけカメラ枠内に入れて **2〜3秒** 止める
6. **検出履歴** に自動的に判定が追加されます:
   - `Azure AI Vision:` の行 → 画像から抽出された caption / tags / objects
   - `Azure OpenAI:` の行 → カタログ内の食材名へ正規化された結果
7. **在庫** タブを開くと、数量が追加または増加していることを確認できます

撮影が安定しない場合は、自動スキャンをOFFにして **「判定」** ボタンを押すことで手動判定にも切り替えられます。

### カメラが使えない場合のフォールバック

カメラのない環境（PC、リモートデスクトップ等）でも動作確認できるように、画面右側に **「デモ入力」** パネルがあります。

- 「バナナ」「トマト」などのボタンを押すと、その食材がカメラ前を通過したのと同じ動作になります
- **検出履歴** と **在庫** タブの動きを確認できます
- ⚠ デモ入力は AI実演 ではなく動作フローを確認するためのフォールバックです

## 3. 在庫の確認と補正

1. **在庫** タブを開く
2. 上部の **冷蔵 / 冷凍 / 常温** フィルタで保存場所別に切り替え可能
3. 各行の **残量入力欄**（0〜100% スライダ）で、AI認識が完璧でない場合の現場補正ができます
   - 例: トマトが1個半残っている → 残量 50%
4. **「残量保存」** ボタンで反映

これは「100% 自動化」ではなく **「運用が止まらず補正できる」** 設計を体感するためのステップです。

## 4. 確認キュー（Human-in-the-loop）

信頼度の低い候補は **自動で確認キュー** に回ります。

1. **カメラ** タブの下部に **「確認キュー」** セクション
2. キューに項目がある場合、`承認 / 却下` を選択できます
3. 承認した項目だけが在庫に反映されます

判定が完璧でない現場で「**運用が止まらない**」ようにする仕組みです。

## 5. 1週間の献立生成

1. 画面右上の **「献立生成」** ボタンを押す
2. 自動で **献立** タブに遷移し、月曜〜日曜の3食×7日分が表示されます
3. ページ下部に **買い足しリスト** が生成されます
   - 在庫でまかなえる食材は除外され、不足分のみリスト化
4. 各献立スロット（朝/昼/夜）をクリックすると **レシピ** タブへ遷移

献立生成のロジックは Azure OpenAI で、以下を考慮します:
- 現在の在庫
- 家族構成・好み・栄養目標・調理時間・予算（**家族** タブで設定）
- 食材の期限優先度

## 6. レシピ詳細

1. **レシピ** タブを開く（または献立から遷移）
2. 左側にレシピリスト、右側に詳細
3. 詳細には以下が表示されます:
   - 材料リスト（在庫の有無を緑/赤で表示）
   - 手順（番号付き）
   - 栄養目安（カロリー、タンパク質、野菜量など）
   - 検索元の出典（クッキングAPI連携を想定した設計）

## 7. 使用デモ（調理時の検出）

調理で使った食材をカメラで検知し、在庫から自動で差し引くデモです。

1. **カメラ** タブに戻る
2. モードを **「使用」** に切り替える
3. 在庫にある食材を1種類カメラに映して 2〜3秒止める
4. **「判定」** を押す
5. **検出履歴** に `Azure AI Vision:` / `Azure OpenAI:` の判定根拠が表示
6. **在庫** タブで数量が **減っている** ことを確認
7. 使い切った食材は自動で在庫から削除されます

デモ入力でも同じ流れを試せます（「使用」モードのデモボタン）。

## 8. 家族・施設プロファイル（オプション）

献立生成のパラメータを変更したい場合:

1. **家族** タブを開く
2. 以下を編集:
   - 家族構成（大人 / 子供 / 高齢者の人数）
   - 好みのジャンル / 苦手な食材
   - 1食あたりの目標カロリー・タンパク質
   - 1食あたりの調理時間上限
   - 1週間の食費予算
3. **「保存」** ボタン
4. 次回の献立生成からこの条件が反映されます

## 9. 動作確認チェックリスト（審査員向け）

| 項目 | 確認方法 | 期待結果 |
|------|---------|---------|
| Microsoft AI が configured | 画面右下パネル | Azure OpenAI / Azure AI Vision 両方 configured |
| Azure AI 実利用 | カメラで食材を映す | 検出履歴に `Azure AI Vision:` / `Azure OpenAI:` の行 |
| 在庫DB更新 | 在庫タブを開く | 認識した食材が追加・増加している |
| Human-in-the-loop | 確認キュー | 承認/却下で在庫制御できる |
| 残量補正 | 在庫タブのスライダ | 残量入力が保存される |
| 1週間献立生成 | 「献立生成」ボタン | 月〜日の3食×7日 + 買い足しリスト |
| レシピ詳細 | 献立から遷移 | 材料・手順・栄養が表示 |
| 使用検知 | 使用モードでカメラ | 在庫から差し引きされる |
| カメラなし環境対応 | デモ入力ボタン | カメラなしでも全機能を確認できる |

## トラブルシューティング

### カメラ許可ダイアログが出ない / 黒いまま

- ブラウザの URL バー横のカメラアイコンから手動で許可
- HTTPS（azurewebsites.net）なのでブラウザのカメラAPIは利用可能
- それでも動かない場合は **デモ入力** で代替

### 検出履歴に Azure AI Vision の行が出ない

- 数秒待つ（自動スキャンは一定間隔で実行）
- 食材を枠内中央に静止させる（動いていると認識が安定しない）
- 「判定」ボタンを押して手動判定に切り替え

### 在庫が増えない

- 確認キューに入っている可能性 → カメラタブ下部の **確認キュー** を確認
- 信頼度が高すぎる重複と判定された可能性 → 別の食材を試す

### 献立生成が失敗する

- 在庫が空の場合は 1〜2 食材を登録してから再実行
- Azure OpenAI のレート制限の可能性 → 30秒待って再実行

### App Service が起動していない（503 等）

- App Service Cold start で初回アクセスから 30〜60 秒かかる場合があります
- リロードして再試行してください
- それでも復旧しない場合は提出者まで連絡（連絡先は提出フォームに記載）
